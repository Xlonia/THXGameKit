## 二、开放问题（请作者裁定）

1. **许可证**：MIT（Godot 生态惯例，最利民）？其他？
2. **仓库形态与节奏**：THX75 保持现状、GameKit 新仓起步，之后 THX75 改造成
   "内核+自走棋插件"的参考实现？迁移节奏=渐进（先在 th75 内立 addons/ 边界
   再外移）还是一次性大迁移？
3. **C++ 扩展分发**：releases 附预编译 dll（Win）？要求用户自编译（SCons 文档）？
   跨平台（Linux/macOS）排期？（无扩展时 GD 回退路径已具备=可纯 GDScript 跑）
4. **数据格式归属**：CSV 五表结构与《类型一览》是内核规范还是 THX75 数据？
   .thx 格式进内核无疑问；角色表结构（部位/AP/P点列）属自走棋插件还是内核？
5. **热力图族位置**：内核 or 插件？（我建议插件"Insight"；它依赖 DDM 但 DDM
   不依赖它）
6. **编辑器位置**：内核必件 or 可选组件（纯代码用户可不装）？
7. **东方 IP 纯净性**：内核与 GameKit 仓不得含东方角色名/弹幕名/设定文本；
   THX75 仓已公开——是否需要剥离/保留东方数据（ZUN 二创指南下通常可保留，
   但要作者拍板）？
8. **Godot 版本锚定**：4.7 专属 or 4.x 兼容范围？
9. **文档语言**：中文为主（+英文 README 摘要）？
10. **本轮之后的第一步**：我建议先做"内核边界在 th75 内的目录化"（零行为变化
    的 moves + autoload 拆分），验证边界后再外移成 addon——还是直接在 GameKit
    仓搭 addon 骨架从 th75 拷贝？作者偏好？

## 三、原则（提案）

- 内核零"东方"字符串、零玩法假设（不知道 P 点/态势卡为何物）
- 内核 API 以"弹幕事件/实体/弹幕图/时间轴"为一等公民
- 插件间不互相依赖，只依赖内核
- 游戏只依赖插件与内核，不 fork 内核


## 〔决议 2026-11-11（作者裁定）〕

- **Q1 许可证**：MIT。后续或有类 ZUN 二创规约，其最终指向仍为类 MIT 许可。
- **Q2 外来插件**：**不得拷入本内核**（dialogic / godot-2d-rpg / godot_ai_workbench
  等第三方源码非本系列劳动成果）——需要同类能力时**内生重写**。
- **Q3 平台**：仅 Windows（暂无跨平台测试人手）。
- **Q4 角色表**：最狭义本体列 = 本地化键名 + 中日英三语名 + 快机速度(Cruise) +
  慢机速度(Normal) + 火力点排布；其余列**保留在文件中**，由对应玩法插件读取。
- **Q5 热力图族**：插件（自走棋特有的 AI 抽象层）。
- **Q6 编辑器**：内核**必备**件（本内核定位=基于 Godot 的次级引擎）。
- **Q7 东方数据**：内核仓仅保留 **Youshio（晚汐）** 的数据作为数据范例；
  其余东方数据留在 THX75。
- **Q8 兼容范围**：声明兼容范围并随版本更新；保留兼容旧版的代码。
- **Q9 文档**：中日英三语，分三个 md（README.md / README.ja.md / README.en.md）。
- **Q10 第一步**：**迁移弹幕的处理数据基底**（已完成→docs/MIGRATION-STEP1.md）。

## 〔补充决议〕

- 外来插件不得拷入（Q2 引申）：岚露/消望/竹林三个官方插件全部内生实现。
- 本内核为 THX 系列 submodule（安装方式见 README 安装节）。
- 内核仓示例数据 = 晚汐（角色行 + demo_youshio1 事件 + 材质 + 贴图）。
